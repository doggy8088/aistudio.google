    建立嵌入批次¶

    POST https://generativelanguage.googleapis.com/v1beta/models/{model}:asyncBatchEmbedContent

    將一批 EmbedContent 請求排入佇列，以進行批次處理。 BatchEmbedContents 處理常式已存在於 GenerativeService 中，但該處理常式為同步處理。因此將此處命名為 Async，以避免混淆。

    參數¶

    model: required string

    模型 ID，例如 gemini-2.5-flash。組成資源名稱 models/{model}。

    請求主體¶

    batch: required EmbedContentBatch

    要建立的批次。

    請求範例 

    curl -X POST "https://generativelanguage.googleapis.com/v1beta/models/$MODEL_ID:asyncBatchEmbedContent" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "batch": {
    "model": "string",
    "displayName": "string",
    "inputConfig": {
      "fileName": "string"
    }
  }
}'

    回應¶

    error: Status 操作在失敗或取消時的錯誤結果。

    code: integer

    狀態碼，應為 google.rpc.Code 的列舉值。

    message: string

    面向開發人員的錯誤訊息，應以英文撰寫。任何面向使用者的錯誤訊息都應予以在地化，並放在 google.rpc.Status.details 欄位中傳送，或由用戶端進行在地化。

    details: object array

    承載錯誤詳細資訊的訊息清單。API 可使用一組常見的訊息類型。

    response: AsyncBatchEmbedContentResponse
    output: EmbedContentBatchOutput 僅供輸出。批次請求的輸出。
    output: Union type 批次請求的輸出。

    聯集欄位 output 只能是下列其中之一：

    responsesFile: string

    僅供輸出。包含回應之檔案的檔案 ID。該檔案為 JSONL 檔案，每行包含一個回應。回應將為格式化為 JSON 的 EmbedContentResponse 訊息。回應的寫入順序與輸入請求相同。

    inlinedResponses: InlinedEmbedContentResponses 僅供輸出。批次中各請求的回應。當批次是使用內嵌請求建立時才會傳回。回應的順序與輸入請求相同。
    inlinedResponses: InlinedEmbedContentResponse array 僅供輸出。批次中各請求的回應。
    output: Union type 請求的輸出。

    聯集欄位 output 只能是下列其中之一：

    error: Status 僅供輸出。處理請求時遇到的錯誤。

    code: integer

    狀態碼，應為 google.rpc.Code 的列舉值。

    message: string

    面向開發人員的錯誤訊息，應以英文撰寫。任何面向使用者的錯誤訊息都應予以在地化，並放在 google.rpc.Status.details 欄位中傳送，或由用戶端進行在地化。

    details: object array

    承載錯誤詳細資訊的訊息清單。API 可使用一組常見的訊息類型。

    response: EmbedContentResponse

    僅供輸出。請求的回應。

    metadata: object

    僅供輸出。與請求相關聯的中繼資料。

    name: string

    由伺服器指派的名稱，僅在最初傳回它的同一個服務內具唯一性。若使用預設的 HTTP 對應，name 應為以 operations/{unique_id} 結尾的資源名稱。

    metadata: EmbedContentBatch

    done: boolean

    若值為 false，表示操作仍在進行中。若為 true，表示操作已完成，且 error 或 response 其中之一可用。

    資料模型¶

    EmbedContentResponse¶

    EmbedContentRequest 的回應。

    Properties:

    embedding: ContentEmbedding

    僅供輸出。由輸入內容產生的嵌入向量。

    usageMetadata: EmbeddingUsageMetadata

    僅供輸出。請求的使用量中繼資料。

    ContentEmbedding¶

    表示嵌入向量的一組浮點數清單。

    Properties:

    values: number array

    嵌入向量值。此欄位僅供 3P 使用者使用，1P 呼叫時不會填入。

    shape: integer array

    此欄位儲存軟權杖張量框架的形狀（例如 [1, 1, 256, 2048]）。

    TaskType¶

    Possible values:

    • TASK_TYPE_UNSPECIFIED: 未設定的值，將預設為其他列舉值之一。
    • RETRIEVAL_QUERY: 指定給定的文字為搜尋／擷取情境中的查詢。
    • RETRIEVAL_DOCUMENT: 指定給定的文字為所搜尋語料庫中的文件。
    • SEMANTIC_SIMILARITY: 指定給定的文字將用於 STS。
    • CLASSIFICATION: 指定給定的文字將進行分類。
    • CLUSTERING: 指定嵌入向量將用於分群。
    • QUESTION_ANSWERING: 指定給定的文字將用於問答。
    • FACT_VERIFICATION: 指定給定的文字將用於事實查核。
    • CODE_RETRIEVAL_QUERY: 指定給定的文字將用於程式碼擷取。

    EmbedContentBatch¶

    表示一批 EmbedContent 請求的資源。

    Properties:

    model: required string

    用於產生完成結果的 Model 名稱。格式：models/{model}。

    displayName: required string

    此批次由使用者定義的名稱。

    inputConfig: required InputEmbedContentConfig 要執行批次處理之執行個體的輸入設定。
    source: required Union type 輸入的來源。

    聯集欄位 source 只能是下列其中之一：

    fileName: string

    包含輸入請求的 File 名稱。

    requests: InlinedEmbedContentRequests 要在批次中處理的請求。
    requests: required InlinedEmbedContentRequest array 要在批次中處理的請求。
    request: required EmbedContentRequest 要在批次中處理的請求。

    model: required string

    模型的資源名稱。此名稱作為要使用的 Model 的 ID。此名稱應與 ListModels 方法傳回的模型名稱相符。格式：models/{model}

    content: required Content 要嵌入的內容。僅會計算 parts.text 欄位。
    parts: Part array 組成單一訊息的有序 Parts。各 Part 可能具有不同的 MIME 類型。
    data: Union type

    聯集欄位 data 只能是下列其中之一：

    text: string

    內嵌文字。

    inlineData: Blob 內嵌媒體位元組。

    mimeType: string

    來源資料的 IANA 標準 MIME 類型。支援的類型範例如下：

    • 圖片： image/png, image/jpeg, image/jpg, image/webp, image/heic, image/heif, image/gif, image/avif
    • Audio: audio/*, video/audio/s16le, video/audio/wav
    • Video: video/*
    • 文字： text/plain, text/html, text/css, text/javascript, text/x-typescript, text/csv, text/markdown, text/x-python, text/xml, text/rtf, video/text/timestamp
    • 應用程式： application/x-javascript, application/x-typescript, application/x-python-code, application/json, application/x-ipynb+json, application/rtf, application/pdf 如需更多背景資訊，請參閱 Supported file formats。

    data: string

    媒體格式的原始位元組。

    displayName: string

    選填。指定用來向模型指稱此 blob 的名稱（例如 "my_blob.png"）。當 verbalization_mode 設為 REFERENCE_ONLY 時，作為 blob 參照識別碼使用。

    functionCall: FunctionCall 模型傳回的預測 FunctionCall，其中包含表示 FunctionDeclaration.name 的字串，以及引數和其值。

    name: required string

    要呼叫的函式名稱。必須為 a-z、A-Z、0-9，或包含底線和連字號，長度上限為 128。

    id: string

    選填。函式呼叫的唯一識別碼。若已填入，用戶端應執行 function_call，並傳回具有相符 id 的回應。

    args: object

    選填。以 JSON 物件格式表示的函式參數和值。

    functionResponse: FunctionResponse FunctionCall 的結果輸出，其中包含表示 FunctionDeclaration.name 的字串，以及包含函式任何輸出的結構化 JSON 物件，作為提供給模型的上下文使用。

    name: required string

    要呼叫的函式名稱。必須為 a-z、A-Z、0-9，或包含底線和連字號，長度上限為 128。

    response: required object

    updateTime: string

    僅供輸出。批次最後更新的時間。

    batchStats: EmbedContentBatchStats 僅供輸出。批次的統計資訊。

    requestCount: string

    僅供輸出。批次中的請求數量。

    successfulRequestCount: string

    僅供輸出。成功處理的請求數量。

    failedRequestCount: string

    僅供輸出。處理失敗的請求數量。

    pendingRequestCount: string

    僅供輸出。仍待處理的請求數量。

    state: BatchState 僅供輸出。批次的狀態。

    Possible values:

    • BATCH_STATE_UNSPECIFIED: 未指定批次狀態。
    • BATCH_STATE_PENDING: 服務正在準備執行批次。
    • BATCH_STATE_RUNNING: 批次正在進行中。
    • BATCH_STATE_SUCCEEDED: 批次已成功完成。
    • BATCH_STATE_FAILED: 批次失敗。
    • BATCH_STATE_CANCELLED: 批次已取消。
    • BATCH_STATE_EXPIRED: 批次已過期。

    priority: string

    選填。批次的優先順序。優先順序值較高的批次將先於優先順序值較低的批次處理。允許負值。預設為 0。

    EmbedContentConfig¶

    EmbedContent 請求的設定。

    Properties:

    title: string

    選填。文字的標題。

    taskType: TaskType 選填。嵌入向量的任務類型。

    Possible values:

    • TASK_TYPE_UNSPECIFIED: 未設定的值，將預設為其他列舉值之一。
    • RETRIEVAL_QUERY: 指定給定的文字為搜尋／擷取情境中的查詢。
    • RETRIEVAL_DOCUMENT: 指定給定的文字為所搜尋語料庫中的文件。
    • SEMANTIC_SIMILARITY: 指定給定的文字將用於 STS。
    • CLASSIFICATION: 指定給定的文字將進行分類。
    • CLUSTERING: 指定嵌入向量將用於分群。
    • QUESTION_ANSWERING: 指定給定的文字將用於問答。
    • FACT_VERIFICATION: 指定給定的文字將用於事實查核。
    • CODE_RETRIEVAL_QUERY: 指定給定的文字將用於程式碼擷取。

    autoTruncate: boolean

    選填。若輸入內容長於最大序列長度，是否靜默截斷輸入內容。

    outputDimensionality: integer

    選填。輸出嵌入向量的縮減維度。若已設定，輸出嵌入向量中多餘的值將從尾端截斷。

    documentOcr: boolean

    選填。是否為文件內容啟用 OCR。

    audioTrackExtraction: boolean

    選填。是否從影片內容中擷取音訊。

    EmbeddingUsageMetadata¶

    嵌入請求的使用量中繼資料。

    Properties:

    promptTokenCount: integer

    僅供輸出。提示詞中的權杖數量。

    promptTokenDetails: ModalityTokenCount array 僅供輸出。請求輸入中已處理的模態清單。
    modality: GenerativeLanguageModality 與此權杖數量相關聯的模態。

    Possible values:

    • MODALITY_UNSPECIFIED: 未指定的模態。
    • TEXT: 純文字。
    • IMAGE: 圖片。
    • VIDEO: 影片。
    • AUDIO: 音訊。
    • DOCUMENT: 文件，例如 PDF。

    tokenCount: integer

    權杖數量。
