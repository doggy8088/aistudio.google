    Batch API¶

    Gemini API 支援批次 API，可讓你在單次呼叫中處理多個要求。詳情請參閱 Batch API 指南。

    方法¶

    方法 HTTP 要求
    建立內容生成批次 POST /v1beta/models/{model}:batchGenerateContent 將一批 GenerateContent 要求排入佇列，進行批次處理。
    建立嵌入批次 POST /v1beta/models/{model}:asyncBatchEmbedContent 將一批 EmbedContent 要求排入佇列，進行批次處理。
    取得批次 GET /v1beta/batches/{generateContentBatch} 取得長時間執行作業的最新狀態。
    列出批次 GET /v1beta/batches 列出符合要求中所指定篩選條件的作業。
    取消批次 POST /v1beta/batches/{generateContentBatch}:cancel 開始非同步取消長時間執行作業。
    刪除批次 DELETE /v1beta/batches/{generateContentBatch} 刪除長時間執行作業。
    更新內容生成批次 PATCH /v1beta/batches/{generateContentBatch}:updateGenerateContentBatch 更新一批用於批次處理的 GenerateContent 要求。
    更新嵌入批次 PATCH /v1beta/batches/{generateContentBatch}:updateEmbedContentBatch 更新一批用於批次處理的 EmbedContent 要求。

    資源¶

    GenerateContentBatch¶

    代表一批 GenerateContent 要求的資源。

    屬性：

    model：必填 string

    用於生成補全內容的 Model 名稱。格式：models/{model}。

    displayName：必填 string

    使用者為這個批次定義的名稱。

    inputConfig：必填 InputConfig 要執行批次處理的執行個體的輸入設定。
    source：必填 Union type 輸入的來源。

    Union 欄位 source 只能是下列其中之一：

    fileName：string

    包含輸入要求的 File 名稱。

    requests：InlinedRequests 要在批次中處理的要求。
    requests：必填 InlinedRequest array 要在批次中處理的要求。
    request：必填 GenerateContentRequest 要在批次中處理的要求。

    model：必填 string

    用於生成補全內容的 Model 名稱。格式：models/{model}。

    contents：必填 Content array 目前與模型的對話內容。對於單輪查詢，這是單一執行個體；對於多輪查詢（例如聊天），這是重複欄位，包含對話記錄與最新要求。
    parts：Part array 組成單一訊息的已排序 Parts。各 Part 的 MIME 類型可能不同。
    data：Union type

    Union 欄位 data 只能是下列其中之一：

    text：string

    行內文字。

    inlineData：Blob 行內媒體位元組。

    mimeType：string

    來源資料的 IANA 標準 MIME 類型。支援的類型範例：

    • 圖片：image/png、image/jpeg、image/jpg、image/webp、image/heic、image/heif、image/gif、image/avif
    • 音訊：audio/*、video/audio/s16le、video/audio/wav
    • 影片：video/*
    • 文字：text/plain、text/html、text/css、text/javascript、text/x-typescript、text/csv、text/markdown、text/x-python、text/xml、text/rtf、video/text/timestamp
    • 應用程式：application/x-javascript、application/x-typescript、application/x-python-code、application/json、application/x-ipynb+json、application/rtf、application/pdf 其他背景資訊請參閱支援的檔案格式。

    data：string

    媒體格式的原始位元組。

    displayName：string

    選填。指定用來向模型指稱這個 blob 的名稱（例如「my_blob.png」）。當 verbalization_mode 設為 REFERENCE_ONLY 時，作為 blob 參照識別碼使用。

    functionCall：FunctionCall 模型傳回的預測 FunctionCall，包含代表 FunctionDeclaration.name 的字串，以及引數與其值。

    name：必填 string

    要呼叫的函式名稱。必須由 a-z、A-Z、0-9 組成，或包含底線與破折號，長度上限為 128。

    id：string

    選填。函式呼叫的唯一識別碼。若有填入，用戶端應執行該 function_call，並傳回帶有相符 id 的回應。

    args：object

    選填。JSON 物件格式的函式參數與值。

    functionResponse：FunctionResponse FunctionCall 的結果輸出，包含代表 FunctionDeclaration.name 的字串，以及含有函式任何輸出的結構化 JSON 物件，作為提供給模型的上下文。

    name：必填 string

    要呼叫的函式名稱。必須由 a-z、A-Z、0-9 組成，或包含底線與破折號，長度上限為 128。

    response：必填 object

    JSON 物件格式的函式回應。呼叫端可使用符合函式語法的任意鍵來傳回函式輸出，例如「output」、「result」等。特別是當函式呼叫執行失敗時，回應可包含「error」鍵，將錯誤詳情傳回給模型。多媒體內容可透過子物件納入，該子物件包含單一「$ref」鍵，其值為 inline_data.display_name 或 file_data.display_name，屬於持有該多媒體內容的 FunctionResponsePart。請參閱多模態函式回應。

    id：string

    選填。這個回應所對應的函式呼叫識別碼。由用戶端填入，以比對對應的函式呼叫 id。

    parts：FunctionResponsePart array 選填。組成函式回應的已排序 Parts。各 Part 的 IANA MIME 類型可能不同。
    data：Union type 函式回應 part 的資料。

    Union 欄位 data 只能是下列其中之一：

    inlineData：FunctionResponseBlob 行內媒體位元組。

    mimeType：string

    來源資料的 IANA 標準 MIME 類型。範例：

    • image/png
    • image/jpeg

    若提供不支援的 MIME 類型，將傳回錯誤。完整支援類型清單請參閱支援的檔案格式。

    data：string

    媒體格式的原始位元組。

    displayName：string

    選填。blob 的顯示名稱。用來提供標籤或檔名以區分各個 blob，並從 FunctionResponse.response 參照該 blob（例如透過 {"$ref": "DISPLAY_NAME"}）。

    fileData：FunctionResponseFileData 以 URI 為基礎的資料。

    fileUri：必填 string

    URI。

    mimeType：string

    來源資料的 IANA 標準 MIME 類型。若提供不支援的 MIME 類型，將傳回錯誤。完整支援類型清單請參閱多模態函式回應與支援的檔案格式。

    displayName：string

    選填。檔案的顯示名稱。用來提供標籤或檔名以區分檔案資料，並從 FunctionResponse.response 參照該檔案（例如透過 {"$ref": "DISPLAY_NAME"}）。

    metadata：Union type 控制資料的額外預處理。當 inline_data 或 file_data 存在時設定這個欄位，以設定每個 part 的靜態媒體預處理。

    Union 欄位 metadata 只能是下列其中之一：

    videoMetadata：VideoMetadata 選填。影片中繼資料。僅當影片資料以 inline_data 或 file_data 呈現時，才應指定中繼資料。

    startOffset：string

    選填。影片的起始偏移。

    endOffset：string

    選填。影片的結束偏移。

    fps：number

    選填。傳送給模型的影片影格率。若未指定，預設值為 1.0。fps 範圍為 (0.0, 24.0]。

    contentLayers：string enum array 選填。要傳回的內容層。若為空，預設為 [FRAMES, AUDIO]。

    可能的值：

    • CONTENT_LAYER_UNSPECIFIED：預設值。
    • FRAMES：擷取影片影格。
    • AUDIO：擷取音軌。
    • TRANSCRIPT：擷取音訊逐字稿。
    documentMetadata：DocumentMetadata 選填。文件中繼資料。僅當文件資料以 inline_data 或 file_data 呈現時，才應指定中繼資料。

    startPage：integer

    選填。起始頁，以 1 起算，包含起始頁。

    endPage：integer

    選填。結束頁，以 1 起算，包含結束頁。

    contentLayers：string enum array 選填。要傳回的內容層。若為空，當設定了 DocumentMetadata 時預設為 [PAGE_IMAGE]；若未設定 DocumentMetadata，則使用預設的文件處理方式（例如 PDF 的頁面影像）。

    可能的值：

    • CONTENT_LAYER_UNSPECIFIED：預設值。
    • PAGE_IMAGE：轉譯後的頁面影像。
    • PAGE_TEXT：擷取的頁面文字。
    spreadsheetMetadata：SpreadsheetMetadata 選填。試算表中繼資料。僅當試算表資料以 inline_data 或 file_data 呈現時，才應指定中繼資料。

    visibleCells：string

    選填。要擷取的儲存格範圍，以 A1 標記法表示（例如 "A1:D10"）。若未設定，將使用工作表已佔用的完整範圍。

    sheetIndex：integer

    選填。要擷取的工作表索引，以 1 起算，依活頁簿順序。若未設定，會擷取全部工作表。

    contentLayers：string enum array 選填。要傳回的內容層。若為空，當設定了 SpreadsheetMetadata 時預設為 [DATA, FORMULAS]。

    可能的值：

    • CONTENT_LAYER_UNSPECIFIED：預設值。
    • DATA：儲存格值、合併儲存格與格式。
    • FORMULAS：公式運算式及其計算結果。
    • VISUAL：工作表的轉譯影像。
    audioMetadata：AudioMetadata 選填。音訊中繼資料。僅當音訊資料以 inline_data 或 file_data 呈現時，才應指定中繼資料。

    startOffset：string

    選填。音訊的起始偏移。

    選填。套用到下一個權杖 logprobs 的頻率懲罰，乘以每個權杖到目前為止在回應中出現的次數。正懲罰會抑制使用已使用過的權杖，程度與權杖的使用次數成比例：權杖用得越多，模型再次使用該權杖的難度越高，從而增加回應的詞彙量。注意：負懲罰會鼓勵模型重複使用權杖，程度與權杖的使用次數成比例。小的負值會減少回應的詞彙量；較大的負值會使模型開始重複一個常見權杖，直到達到 max_output_tokens 上限。
