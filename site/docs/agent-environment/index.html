    受管理代理的環境¶

    環境是 Linux 沙箱，為代理提供一個隔離的空間來執行 程式碼並儲存檔案。環境與互動情境彼此獨立，因此您可以 在多次互動中重複使用同一個環境，也能隨時重新 開始。沙箱預設由 Google 代管，您也可以連接 自行代管環境，在 您自己的基礎架構中執行工具。

    以下範例示範如何以全新的遠端環境建立互動， 並取得其 ID：

    from google import genai

client = genai.Client(http_options={"api_version": "v1beta"})

interaction = client.interactions.create(
    agent="antigravity-preview-09-2026",
    input="Install pandas and matplotlib, verify the imports, and print the versions.",
    environment="remote",
)

print(f"Environment ID: {interaction.environment_id}")

    import { GoogleGenAI } from "@google/genai";

    environment: "remote",

console.log(`Environment ID: ${interaction.environment_id}`);

    .environment(CreateAgentInteractionEnvironment.of("remote"))

    environment 參數¶

    environment 參數接受三種形式：

    形式 範例 使用時機
    "remote" environment="remote" 佈建一個全新的沙箱。
    環境 ID environment="env_abc123" 重複使用既有沙箱，連同其中的所有檔案與套件。
    設定物件 environment={...} 佈建新沙箱，可帶入來源、網路規則、環境變數，或三者的組合。

    以下範例示範 environment 參數的三種 用法。

    您也可以將 .agents/hooks.json 設定檔與自訂攔截指令碼掛載到沙箱中，在工具執行時強制套用安全防護措施或執行自動化驗證。結構定義與程式碼範例請參閱 Hooks。

    環境變數¶

    使用 env 欄位在沙箱內設定環境變數。每個項目 會將變數名稱對應到一個值：可以是設定用的字面字串， 也可以是密鑰用的已儲存 憑證 引用。代理 看待這些變數的方式與在任何 shell 中相同，因此會從 行程環境讀取的工具與指令碼都能直接取得，無需額外串接。

    兩種值類型的行為並不相同。字面字串會以純文字寫入 容器。憑證引用則不同：變數收到的是一個 佔位符，egress proxy 只有在向該憑證信任網域發出外送要求時， 才會代入真正的密鑰。詳情請參閱 將憑證用作環境變數， 了解其運作方式。

    網路設定¶

    預設情況下，環境的外送網路存取不受限制。使用 network 欄位可將外送流量限制在特定網域。每條規則 會指定一個 domain，並可選擇性加上 credential 以注入已儲存的密鑰， 以及選擇性的 transform 物件，將標頭注入符合的要求。 這些標頭可依每次互動而有所不同，您也可以針對同一個環境更新它們。

    欄位 類型 說明
    domain string 要比對的網域。使用完整主機名稱，或以 * 代表所有網域。
    credential string 已儲存的 憑證 的 ID。egress proxy 會在要求發出時解析它，並注入驗證標頭。
    transform object 包含扁平鍵值對的物件，代表要注入符合要求的標頭，例如 {"Authorization": "Bearer ..."}。

    憑證¶

    驗證外送流量有兩種方式：以 ID 引用的已儲存憑證， 以及允許清單規則上的內嵌 transform。egress proxy 在傳輸時會套用兩者，因此無論哪一種情況，密鑰都不會進入 沙箱，也不會出現在您的互動酬載中。

    如果您想將密鑰儲存一次並重複使用，受管理的憑證 就是最適合的選擇。您專案中的每個環境、代理與 觸發器都能引用同一個 ID，而您只需在一個 地方輪替它即可。

    存取 token 與短效 API 金鑰等內嵌 token 會到期。 您可以在下一次互動時，一併傳入既有的 environment_id 與 新的 network 設定來刷新它們。新的網路規則 會完全取代先前的規則，而環境的檔案系統狀態 （已安裝的套件、檔案、存放庫）則會保留。

    環境生命週期¶

    環境遵循以下生命週期：

    狀態 行為
    已建立 當互動指定 environment: "remote" 或設定物件時佈建。
    使用中 互動進行期間持續運行。
    閒置 閒置 15 分鐘後自動建立快照並停止。
    離線 自上次使用中起保留 7 天。可傳入其 ID 來恢復。
    已刪除 在 7 天 TTL 保留期到期後自動從系統移除，或在手動刪除時移除。

    Environments API¶

    您可以使用 Environments API 以程式化方式管理沙箱工作階段。 列舉環境能讓您找出使用中的工作階段 ID，並在用戶端連線 於長時間執行的工作期間中斷時恢復狀態。您也可以 檢視工作階段的中繼資料，並在工作流程 結束時明確刪除環境，不必等待 TTL 自動到期。

    行為對照表¶

    下列行為對照表彙整了檔案與目錄端點、HTTP 方法與查詢參數組合下，預期的回應與封存行為：

    要求 alt recursive extract overwrite 回應
    GET /files （無） （無） - - 根目錄的 JSON 清單
    GET /files/{path}（檔案） （無） - - - 檔案的 JSON 中繼資料
    GET /files/{path}（目錄） （無） false - - 直接子項目的 JSON 清單
    GET /files/{path}（目錄） （無） true - - 所有子孫項目的 JSON 清單
    GET /files/{path}?alt=media（檔案） media - - - 原始檔案內容
    GET /files/{path}?alt=media（目錄） media false - - 目錄中直接檔案的 tar 封存檔
    GET /files/{path}?alt=media（目錄） media true - - 遞迴包含所有檔案的 tar 封存檔
    GET /files?alt=media media false - - 僅根層級檔案的 tar 封存檔
    PUT /files/{path}（檔案） - - false false 將檔案寫入該路徑。若已存在，傳回 409 Conflict
    PUT /files/{path}?overwrite=true - - false true 將檔案寫入或覆寫至該路徑
    PUT /files/{path}?extract=true - - true false 將封存檔解壓縮到目標目錄。若有任何目標檔案已存在，傳回 409 Conflict
    PUT /files/{path}?extract=true&overwrite=true - - true true 解壓縮封存檔，取代任何既有檔案

    以可續傳工作階段上傳大型檔案¶

    對於大型酬載，或在連線不穩定的情況下上傳時，請使用 可續傳工作階段，不要在單次要求中送出整個主體。可續傳 上傳會將傳輸切分為可個別重試的區塊，因此即使 中途失敗，也不必從頭開始。

    先以 uploadType=resumable 啟動工作階段。送出空白主體， 並使用 X-Upload-Content-Type 與 X-Upload-Content-Length 標頭， 宣告您要上傳之酬載的媒體類型與總大小：

    PUT /upload/v1beta/environments/$ENV_ID/files/workspace/data/large_dataset.bin?uploadType=resumable HTTP/1.1
Host: generativelanguage.googleapis.com
X-Upload-Content-Type: application/octet-stream
X-Upload-Content-Length: 20971520
Content-Length: 0
x-goog-api-key: $GEMINI_API_KEY

    回應會在 Location 標頭中帶有工作階段 URL。此 URL 已 包含 upload_id，因此不需要再次提供 API 金鑰：

    HTTP/1.1 200 OK
Location: https://generativelanguage.googleapis.com/upload/v1beta/environments/$ENV_ID/files/workspace/data/large_dataset.bin?uploadType=resumable&upload_id=AJjja9bfHjiYlGi60pUazCaTuPY
Content-Length: 0

    將酬載分塊上傳至該 URL。每個區塊會以 Content-Range 標頭宣告其位元組範圍 與總大小：

    PUT /upload/v1beta/environments/$ENV_ID/files/workspace/data/large_dataset.bin?uploadType=resumable&upload_id=AJjja9bfHjiYlGi60pUazCaTuPY HTTP/1.1
Host: generativelanguage.googleapis.com
Content-Type: application/octet-stream
Content-Range: bytes 0-10485759/20971520
Content-Length: 10485760

<10 MB binary payload>

    除最後一個區塊外，每個區塊都會傳回 308 Resume Incomplete。Range 標頭 會告訴您伺服器已提交了多少位元組，若某個區塊失敗， 就從該處續傳：

    HTTP/1.1 308 Resume Incomplete
Range: bytes=0-10485759
Content-Length: 0

    以相同方式送出其餘區塊：

    PUT /upload/v1beta/environments/$ENV_ID/files/workspace/data/large_dataset.bin?uploadType=resumable&upload_id=AJjja9bfHjiYlGi60pUazCaTuPY HTTP/1.1
Host: generativelanguage.googleapis.com
Content-Type: application/octet-stream
Content-Range: bytes 10485760-20971519/20971520
Content-Length: 10485760

<remaining 10 MB binary payload>

    最後一個區塊會完成上傳並傳回檔案中繼資料，格式與單次上傳相同， 採用相同的 files 包裝：

    {
  "files": [
    {
      "name": "large_dataset.bin",
      "path": "workspace/data/large_dataset.bin",
      "type": "FILE",
      "size_bytes": "20971520",
      "mime_type": "application/octet-stream"
    }
  ]
}

    可續傳工作階段同樣適用於 extract 與 overwrite。請在啟動要求上設定這些查詢 參數，不要設定在個別區塊上。

    覆寫保護¶

    預設情況下，overwrite 為 false。如果目標路徑已存在， 要求會傳回 409 Conflict 錯誤，且不會寫入任何內容：

    {
  "error": {
    "message": "Requested entity already exists",
    "code": "aborted"
  }
}

    若要取代既有檔案或目錄，請設定 overwrite=true（或在 REST 中附加 ?overwrite=true）。搭配 extract=true 時，衝突檢查會套用到 封存檔中的每個檔案，因此只要有任何目標檔案已存在，要求就會失敗。

    下載完整快照（已淘汰）¶

    注意：舊版 /files/environment-{id}:download 端點已淘汰。請改用 環境檔案端點 下載目錄或個別檔案。

    若要將既有程式碼遷移到環境檔案 API：

    • Python：將舊版檔案下載要求改為：

      archive = client.environments.files.download(
    environment="YOUR_ENVIRONMENT_ID",
    path="workspace",
)
with open("snapshot.tar", "wb") as f:
    f.write(archive)

    • JavaScript：將舊版檔案下載要求改為：

      const bytes = await client.environments.files.download({
    environment: "YOUR_ENVIRONMENT_ID",
    path: "workspace",
});
fs.writeFileSync("snapshot.tar", Buffer.from(bytes));

    • REST：將 GET /v1beta/files/environment-$ENV_ID:download?alt=media 改為：

      curl -L -X GET "https://generativelanguage.googleapis.com/v1beta/environments/$ENV_ID/files?alt=media" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -o snapshot.tar

    自行代管環境¶

    除了使用 Google 代管的沙箱，您也可以連接自行代管 環境，讓受管理代理在您掌控的運算 基礎架構內執行工具。您的沙箱透過外送 HTTPS 連線，使用開放原始碼的 Gemini API CLI，且不需要開啟任何入站防火牆 連接埠。

    連接自行代管環境的步驟如下：

    1. 呼叫 POST /v1beta/environments 並帶入 {"mode": "self_hosted"}，取得 環境 id 與一次性 environment_key。
    2. 在您的沙箱內執行 gemini-api environments connect（來自 google-gemini/gemini-api-cli）， 並使用該 environment_key。
    3. 將該環境的 id 傳入 environment，再呼叫 interactions.create。

    注意：託管沙箱選項（sources、network、env 與 /files 快照）僅適用於 Google 代管環境。自行代管環境 會以 400 INVALID_ARGUMENT 拒絕這些選項。

    以下範例說明如何連接沙箱供應商：

    • Google Cloud Run
    • Agent Substrate
    • Cloudflare Sandbox
    • Daytona
    • E2B
    • Fly.io (Sprites and Machines)
    • Modal
    • Vercel Sandbox

    您也可以在 Docker or rootless Podman 中執行執行階段。 若要進行測試，您可以 在本機執行。 本機模式會直接在您的主機上執行 execute_bash，除非您傳入 --disable-bash。設定說明請參閱 自行代管環境指南， 該指南也包含參考架構與 部署資訊清單。

    定價與資源¶

    每個 Google 代管環境都以固定的 CPU 與記憶體配置運行。 在預覽期間，Google 不會針對代管環境的運算收費。 代理 token 費用請參閱定價。

    限制¶

    • 預覽狀態：環境與受管理代理目前為預覽版。功能與結構定義可能變更。
    • 內嵌來源大小：內嵌來源每個檔案上限為 1 MB，所有檔案總計上限為 2 MB。
    • 來源大小：Git 存放庫上限為 500 MB，Cloud Storage 存放庫上限為 2 GB。
    • 環境啟動：佈建新環境最多約需 5 秒。大型來源存放庫可能拉長此時間。
    • 環境到期：未使用中的離線環境會保留 7 天，之後透過自動 TTL 清理到期失效。傳入已到期或 無效的環境 ID 會傳回 404 Not Found 錯誤。
    • 檔案支援：代理目前僅能讀取文字與圖片檔案，尚未支援二進位檔案。
    • 不可從根目錄掛載：新增自訂來源時，您不能將根目錄（/）設為 target，必須一律指定子目錄。
