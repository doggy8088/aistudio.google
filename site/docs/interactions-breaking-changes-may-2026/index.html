    Interactions API：重大變更遷移指南（2026 年 5 月）¶

    重大變更：本指南所述的變更屬於 Interactions API 的重大變更，舊版結構將於 2026 年 6 月 8 日移除。請使用 Api-Revision 要求標頭來管理遷移作業。

    v1beta Interactions API 將導入重大變更，重新調整 API 的結構，以支援執行中途引導、非同步工具呼叫等未來功能。本頁說明變更內容，並提供變更前後的程式碼範例，協助你完成遷移。變更分為兩大類：

    1. Steps 結構：新的 steps 陣列取代 outputs 陣列，為每一輪互動提供結構化的時間軸。
    2. 輸出格式設定：新的多型 response_format 整合所有輸出格式控制項，並移除 response_mime_type。

    請依照如何遷移至新結構中的步驟，更新你的整合方式。

    核心變更：outputs 改為 steps¶

    新結構將 outputs 陣列改為 steps 陣列。

    • 舊版：回應傳回扁平的 outputs 陣列，僅包含模型產生的內容。
    • 新結構：回應傳回 steps 陣列，其中包含帶有類型判別欄位的結構化步驟。

    POST /interactions 僅傳回輸出步驟；GET /interactions/{id} 則傳回完整的步驟時間軸，包括最初的 user_input 步驟。

    # Request
interaction = client.interactions.create(
    model="gemini-3.8-flash", input="Tell me a joke."
)

# Response access
print(interaction.outputs[-1].text)

    // Request
const interaction = await client.interactions.create({
    model: 'gemini-3.8-flash',
    input: 'Tell me a joke.'
});

// Response access
console.log(interaction.outputs[-1].text);

    串流¶

    串流新增了以下事件類型：

    新的事件類型¶

    • interaction.created
    • interaction.completed
    • step.start
    • step.delta
    • step.stop

    interaction.status_update 維持不變，它會攜帶新的 status（例如 in_progress 或 requires_action）。每個事件都會在 JSON 負載的 event_type 欄位中標示其類型，與 SSE 的 event: 行相符。

    已淘汰的事件類型¶

    下列舊版事件類型由上方列出的新事件取代：

    • interaction.start → interaction.created
    • content.start → step.start
    • content.delta → step.delta
    • content.stop → step.stop
    • interaction.complete → interaction.completed

    串流函式呼叫：將串流與函式呼叫搭配使用時，step.start 事件會傳遞函式名稱，step.delta 事件則以部分 JSON 字串的形式串流傳遞引數（使用 arguments_delta）。你必須累積這些增量，才能取得完整的引數。這與單次呼叫不同，後者會一次收到完整的函式呼叫物件。

    無狀態對話記錄¶

    如果你在用戶端手動管理對話記錄（無狀態使用情境），就必須更新串連先前對話輪次的方式。

    • 舊版：開發人員通常會從回應中收集 outputs 陣列，並在下一輪透過 input 欄位送回。
    • 新結構：現在應從回應中收集 steps 陣列，傳入下一個要求的 input 欄位，並將你新的使用者輪次以 user_input 步驟附加在後。

    輸出格式設定：response_format 的變更¶

    更新後的 API 將所有輸出格式控制項整合為單一的多型 response_format 欄位，讓輸出設定集中在頂層，並使 generation_config 專注於模型行為（例如 temperature、top_p 與 thinking）。

    主要變更¶

    • API 移除了 response_mime_type：你現在可以在 response_format 內的每個格式項目中指定 MIME 類型。
    • response_format 現在是多型物件（或陣列）：每個項目都有一個 type 判別欄位（text、audio、image）以及各類型專屬的欄位。若要要求多種輸出模態，請傳入格式項目組成的陣列。
    • image_config 從 generation_config 移至 response_format：你現在可以指定 aspect_ratio、image_size 等圖片輸出設定，寫在 response_format 項目中（項目需標示 "type": "image"）。

    如何遷移至新結構¶

    SDK 使用者¶

    請升級至最新版 SDK（Python ≥2.0.0、JavaScript ≥2.0.0）。SDK 會自動讓你採用新結構，除了更新讀取回應的方式（見上方範例）之外，無需變更任何程式碼。請注意，這些 SDK 版本僅支援新結構。舊版 SDK（Python 1.x.x、JavaScript 1.x.x）仍可繼續使用，直到舊版結構於 2026 年 6 月 8 日移除為止。

    REST API 使用者¶

    在要求中加入 Api-Revision: 2026-05-20 標頭，即可立即採用新結構。5 月 26 日之後，新結構將成為所有要求的預設。你可以暫時使用 Api-Revision: 2026-05-07 退出，直到 6 月 8 日 API 永久移除舊版結構為止。

    遷移檢查清單¶

    Steps 結構（steps）¶

    • 更新程式碼，改從 steps 陣列（而非 outputs）讀取回應內容。查看範例。
    • 確認你的程式碼能處理 user_input 與 model_output 兩種步驟類型。查看範例。
    • （函式呼叫）更新程式碼，找到 function_call 步驟（位於 steps 陣列中）。查看範例。
    • （伺服器端工具）更新程式碼，處理工具專屬步驟（例如 google_search_call、google_search_result）。查看範例。
    • （無狀態記錄）更新記錄管理方式，將 steps 陣列傳入下一個要求的 input 欄位。查看詳情。
    • （僅限串流）更新用戶端，監聽新的 SSE 事件類型（interaction.created、step.delta 等）。查看範例。

    輸出格式設定（response_format）¶

    • response_mime_type 改以 mime_type 欄位表示，並放在 response_format 內。查看範例。
    • 將現有的 response_format JSON 結構包裝在 {"type": "text", "schema": ...} 物件中。查看範例。
    • （圖片生成）將 image_config 從 generation_config 移至 {"type": "image", ...} 形式的項目，並放入 response_format。查看範例。
    • （語音生成）將 response_modalities=["audio"] 改為 {"type": "audio"} 形式的項目，並放入 response_format。查看範例。
    • （多模態）要求多種輸出模態時，將 response_format 由單一物件改為陣列。
