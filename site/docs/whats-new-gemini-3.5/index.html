    Gemini 3.5 Flash 新功能¶

    已淘汰：Gemini 3.5 Flash (gemini-3.5-flash) 已淘汰，並由 Gemini 3.6 Flash (gemini-3.6-flash) 取代。目前 已無法在 Google AI Studio 中選用，傳送至 gemini-3.5-flash 的 API 要求會自動路由至 gemini-3.6-flash。請將 模型字串更新為 gemini-3.6-flash（或改用 Gemini 3.8 Flash），並參閱 Gemini 3.6 Flash 指南。

    Gemini 3.5 Flash (gemini-3.5-flash) 是 Gemini 3 系列中較早一代的 Flash 模型， 目前已淘汰，並會自動路由至 Gemini 3.6 Flash。

    本指南保留供參考，記錄 Gemini 3.5 Flash 所具備的功能，以及 Gemini 3.x 基礎參數的相關更新。

    模型總覽¶

    模型 模型 ID 說明
    Gemini 3.5 Flash（已淘汰） gemini-3.5-flash 較早一代的 Flash 模型，適用於代理與程式設計工作。已由 Gemini 3.6 Flash 取代。

    Gemini 3.5 Flash 支援 1Mtokens的上下文視窗、最多 65k 個輸出 tokens、思考功能，以及與 Gemini 3 Flash 相同的工具與平台功能，包括 Computer Use。

    完整規格請參閱模型總覽。

    快速入門¶

    from google import genai

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-3.6-flash",
    input="Explain how parallel agentic execution works in three sentences."
)
print(interaction.output_text)

    import com.google.genai.Client;
import com.google.genai.gaos.models.interactions.CreateModelInteraction;
import com.google.genai.gaos.models.interactions.Interaction;
import com.google.genai.gaos.models.interactions.InteractionsInput;
import com.google.genai.gaos.models.interactions.Model;
import com.google.genai.gaos.models.operations.CreateInteractionRequestBody;

Client client = new Client();

CreateModelInteraction params =
    CreateModelInteraction.builder()
        .model(Model.of("gemini-3.5-flash"))
        .input(
            InteractionsInput.of(
                "Explain how parallel agentic execution works in three sentences."))
        .build();

Interaction interaction =
    client.interactions.create(CreateInteractionRequestBody.of(params)).interaction().get();

System.out.println(interaction.outputText().orElse(""));

    package main

import (
    "context"
    "fmt"
    "log"

    "google.golang.org/genai"
    "google.golang.org/genai/interactions/models/interactions"
    "google.golang.org/genai/interactions/models/operations"
)

func main() {
    ctx := context.Background()
    client, err := genai.NewClient(ctx, nil)
    if err != nil {
        log.Fatal(err)

    新功能¶

    • 持續的前沿效能：我們最聰明的 Flash 模型，針對大規模代理與程式設計工作最佳化。
    • 代理執行：可大規模部署子代理、解決問題，並進行快速的代理迴圈。
    • 程式設計：反覆進行程式設計循環、快速探索與製作原型，以測試不同路徑並動態探索解決方案。
    • 長程工作：大規模的多步驟工作流程與工具使用。
    • 思考保留：模型會自動在多輪對話之間保留中間推理過程，無需變更 API。
    • 新的預設思考強度等級：預設思考強度已由 high 改為 medium。詳情請參閱新的預設思考強度等級。
    • 改良的 low 思考：low 現在已針對步驟較少的程式碼與代理工作大幅改良，能以更低的延遲與成本提供優異品質。
    • 正式發布：穩定模型，可用於大規模正式環境。

    選擇合適的 Flash 模型¶

    Gemini 3.5 Flash 已淘汰，並會自動路由至 Gemini 3.6 Flash。我們會依您的成本、延遲與 能力需求，推薦下列模型：

    • Gemini 3.8 Flash：我們最新、最聰明的 Flash 模型，適用於 複雜的程式設計與代理工作流程。請參閱 Gemini 3.8 Flash 指南。
    • Gemini 3.6 Flash：Gemini 3.5 Flash 的直接替代模型，token 用量更少， 輸出價格也更低。請參閱 Gemini 3.6 Flash 與 3.5 Flash-Lite 指南。
    • Gemini 3.5 Flash-Lite / Gemini 3.1 Flash-Lite：若工作成本低、數量大， 且不需要完整的 Flash 推理深度，請使用 Gemini 3.5 Flash-Lite 或 Gemini 3.1 Flash-Lite。

    行為變更¶

    新的預設思考強度等級：medium¶

    預設思考強度現在為 medium，已由 Gemini 3 Flash Preview 的 high 變更。medium 能在各種工作上提供非常好的結果， 同時速度更快、成本效益更高。面對複雜問題時，high 會促使模型進行更深入的思考。

    思考強度等級 適用時機
    minimal 針對回應速度最佳化。適用於聊天類用途、快速的事實型回答，以及較簡單的工具呼叫。
    low 適用於需要較低延遲與較少步驟的程式碼與代理工作。也適用於需要一定思考的分析與寫作工作。
    medium (default) 適用於大多數工作，品質最佳。建議用於複雜的程式碼與代理用途。
    high 將模型的思考與工具使用能力發揮到最大。最適合複雜推理、困難的數學，以及最艱難的程式碼或代理工作。可進行延伸思考與函式呼叫。

    思考保留¶

    模型會自動在多輪對話之間保留中間推理過程。當對話記錄中存在推理上下文時， 該上下文會延續至後續回合，進而提升反覆除錯與程式碼重構等複雜多步驟工作的效能。無需變更 API：

    • Interactions API：思考內容已自動保留，行為不變。
    • GenerateContent API：自 Gemini 3.5 Flash 起，當對話記錄中存在思考簽章時，模型會使用先前所有回合的推理上下文。如要啟用此功能，請在 contents 中傳入完整且未經修改的對話記錄（包括思考簽章）。SDK 會自動處理此事。

    Gemini 3.x 的參數更新與最佳做法¶

    以下內容適用於所有 Gemini 3.x 模型，包括 Gemini 3.5 Flash。

    • temperature, top_p, top_k：我們強烈建議不要變更預設值。Gemini 3 的推理能力已針對預設設定最佳化。
    • 請使用 thinking_level，不要使用 thinking_budget。
    • 函式呼叫回應配對：id、name 與回應數量必須與前面的呼叫相符。
    • 多模態函式回應：請將多模態內容放在函式回應內部，不要放在外部。
    • 函式回應中的行內指令：請附加至函式回應文字，不要另列為獨立部分。
    • 減少不必要的工具呼叫：在代理工作流程中，可使用較低的思考等級，或透過系統指令進行實驗，以減少工具呼叫。

    如何更新程式碼，請參閱下列各節。

    取樣參數（不再建議使用）¶

    所有 Gemini 3.x 模型現在都不再建議使用 temperature、top_p 與 top_k。Gemini 3 的推理能力已針對預設 設定最佳化。請從所有要求中移除這些參數。

    # ⚠️ Remove these parameters (not recommended)
generation_config = {
    "temperature": 0.7,
    "top_p": 0.9,
    "top_k": 40,
}

    如要確保結果具確定性，建議您針對特定用途定義含有明確規則的系統指令。

    thinking_budget（不再建議使用）¶

    所有 Gemini 3.x 模型現在都不再建議使用原始數值型 thinking_budget 參數。請改用 thinking_level 字串列舉。

    # ⚠️ Before (not recommended)
generation_config = {
    "thinking": {"thinking_budget": 7500},
}

# ✅ After
generation_config = {
    "thinking": {"thinking_level": "medium"},
}

    可用值為：minimal、low、medium（預設）與 high。

        CallID: callID,

    減少不必要的工具呼叫¶

    如果您遇到工具呼叫過度使用的情況，以下兩種技巧有助於減少呼叫次數：

    1. 先降低思考等級（medium、low 或 minimal）： 較高的思考等級會促使模型使用更多工具進行探索與 驗證，因此降低等級可減少工具呼叫。

    2. 加入系統指令：如果在調整 思考等級後仍過度使用，請考慮使用限制工具用量的提示詞。例如：

      You have a limited action budget of <n> tool calls. Use them efficiently.

    我們強烈建議更新至 google-genai SDK v2.0.0 或更新版本。 此版本為 Interactions API 引入了破壞性變更。詳情請參閱 破壞性變更遷移指南。

    Gemini 3 系列功能¶

    Gemini 3.5 Flash 繼承了 Gemini 3 系列的全部功能，包括 Computer Use。 Gemini 3 推出並延續至今的功能包括：

    • Thinking： 在 API 呼叫之間保留加密的推理上下文。在 Interactions API 中自動啟用；在 GenerateContent 中則為隱含啟用。
    • Structured outputs with tools： 將 JSON 模式與內建工具（Search、URL context、程式碼執行、函式呼叫）結合使用。
    • Multimodal function responses： 在函式呼叫結果中傳回圖片、音訊與其他媒體。
    • Code execution with images： 執行可處理並產生圖片的程式碼。
    • Combined tool use： 在同一個要求中同時使用內建工具與自訂函式呼叫。
    • Media resolution： 精細控制圖片、影片與 PDF 輸入的 token 配置。Gemini 3 模型支援依內容項目設定解析度（low、medium、high、ultra_high），適用於混合保真度的提示詞。
    • Thought signatures： 加密 呈現模型內部推理的表示方式。在無狀態模式下進行多輪 函式呼叫時為必要項目；Interactions API 與官方 SDK 會自動管理。

    提示詞最佳做法¶

    Gemini 3.x 模型是推理模型，這會改變您撰寫提示詞的方式。

    • 精確的指令：請保持簡潔。Gemini 3.x 對直接、 清楚的指令回應最佳。為舊模型設計的冗長或複雜提示詞工程技巧， 可能導致模型過度分析。
    • 輸出詳盡程度：Gemini 3 與 3.1 預設較不冗長， 偏好直接且有效率的回答。如果您的用途需要 對話式語氣，請在提示詞中明確引導模型（例如， 「請以親切、健談的助理風格說明這件事」）。
    • 上下文管理：處理大型資料集（例如整本 書籍、程式碼集或長影片）時，請將您的具體指令或 問題放在提示詞末尾、資料上下文之後。請以類似「根據 前述資訊……」的句子作為問題開頭，以錨定 模型的推理。

    如要進一步瞭解提示詞設計策略，請參閱 提示詞工程指南。

    限制¶

    • Gemini 3.x 不支援圖片分割。若有分割 工作負載，請繼續使用已關閉思考功能的 Gemini 2.5 Flash，或 Gemini Robotics-ER 1.6。

    常見問題¶

    1. Gemini 3.5 Flash 的知識截止日期為何？ Gemini 3.5 Flash 的 知識截止日期為 2025 年 1 月。如需較新的資訊，請使用 Search Grounding 工具。
    2. 上下文視窗的限制為何？ Gemini 3.5 Flash 支援 1 百萬個 token 的輸入上下文視窗，以及最多 65k 個輸出 tokens。
    3. 我原有的 thinking_budget 程式碼還能運作嗎？ 可以，thinking_budget 目前 仍受支援以維持向後相容性，但我們建議遷移至 thinking_level，以獲得更可預測的效能。請勿在同一個 要求中同時使用兩者。
    4. Gemini 3.5 Flash 是否支援 Batch API？ 支援。詳情請參閱 Batch API 指南。
    5. 是否支援 Context Caching？ 支援，Context Caching 已 支援。
    6. 支援哪些工具？ Gemini 3.5 Flash 支援 Google Search、 Grounding with Google Maps、 File Search、Code Execution、 URL Context，以及標準的 Function Calling，包括 combined tool use 與 Computer Use。
