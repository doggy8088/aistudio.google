    Batch API¶

    這項功能目前僅適用於 generateContent API。 詳情請參閱本頁內容。

    Gemini Batch API 專為大量請求的非同步處理而設計，費用僅為 標準費用的 50%。 目標處理時間為 24 小時，但多數情況下會快上許多。

    Batch API 適合用於不需要即時回應的大規模、非急迫任務， 例如資料預處理或執行評估。

    建立批次工作¶

    在 Batch API 中提交請求有兩種方式：

    • 內嵌請求：直接包含在批次建立請求中的 GenerateContentRequest 物件清單。 這種方式適合總請求大小在 20MB 以下的較小批次。模型傳回的輸出 是 inlineResponse 物件的清單。

    • 輸入檔案：JSON Lines (JSONL) 檔案，每一行都包含一個完整的 GenerateContentRequest 物件。 較大的請求建議使用這種方式。模型傳回的輸出是一個 JSONL 檔案， 其中每一行不是 GenerateContentResponse 就是狀態物件。

    內嵌請求¶

    請求數量較少時，你可以直接將 GenerateContentRequest 物件 內嵌在 BatchGenerateContentRequest 中。 下列範例以內嵌請求呼叫 BatchGenerateContent 方法：

    from google import genai
from google.genai import types

client = genai.Client()

# A list of dictionaries, where each is a GenerateContentRequest
inline_requests = [
    {
        'contents': [{
            'parts': [{'text': 'Tell me a one-sentence joke.'}],
            'role': 'user'
        }]
    },
    {
        'contents': [{
            'parts': [{'text': 'Why is the sky blue?'}],
            'role': 'user'
        }]
    }
]

inline_batch_job = client.batches.create(
    model="gemini-4-hydrogen",
    src=inline_requests,
    config={
        'display_name': "inlined-requests-job-1",
    },
)

print(f"Created batch job: {inline_batch_job.name}")

    輸入檔案¶

    請求數量較大時，請準備一個 JSON Lines (JSONL) 檔案。檔案中的每一行 都必須是一個 JSON 物件，包含使用者自訂的鍵和一個 request 物件，其中 request 是有效的 GenerateContentRequest 物件。 使用者自訂的鍵會用在回應中，標示哪個輸出對應哪個請求的結果。 例如，鍵定義為 request-1 的請求，其回應也會標註相同的鍵名。

    這個檔案透過 File API 上傳。輸入檔案的大小上限為 2GB。

    以下是一個 JSONL 檔案範例。你可以將它儲存為名為 my-batch-requests.json 的檔案：

    {"key": "request-1", "request": {"contents": [{"parts": [{"text": "Describe the process of photosynthesis."}]}]}}
{"key": "request-2", "request": {"contents": [{"parts": [{"text": "What are the main ingredients in a Margherita pizza?"}]}]}}

    與內嵌請求相同，你也可以在每個請求的 JSON 中指定其他參數， 例如系統指令、工具或其他設定。

    你可以如下列範例所示，透過 File API 上傳這個檔案。 如果處理的是多模態輸入，你可以在 JSONL 檔案中參照其他已上傳的檔案。

    import json
from google import genai
from google.genai import types

client = genai.Client()

# Create a sample JSONL file
with open("my-batch-requests.jsonl", "w") as f:
    requests = [
        {"key": "request-1", "request": {"contents": [{"parts": [{"text": "Describe the process of photosynthesis."}]}]}},
        {"key": "request-2", "request": {"contents": [{"parts": [{"text": "What are the main ingredients in a Margherita pizza?"}]}]}}
    ]
    for req in requests:
        f.write(json.dumps(req) + "\n")

# Upload the file to the File API
uploaded_file = client.files.upload(
    file='my-batch-requests.jsonl',
    config=types.UploadFileConfig(display_name='my-batch-requests', mime_type='jsonl')
)

print(f"Uploaded file: {uploaded_file.name}")

    import {GoogleGenAI} from '@google/genai';
import * as fs from "fs";
import * as path from "path";

const ai = new GoogleGenAI({});
const fileName = "my-batch-requests.jsonl";

// Define the requests
const requests = [
    { "key": "request-1", "request": { "contents": [{ "parts": [{ "text": "Describe the process of photosynthesis." }] }] } },
    { "key": "request-2", "request": { "contents": [{ "parts": [{ "text": "What are the main ingredients in a Margherita pizza?" }] }] } }
];

// Construct the path to file
const filePath = fileName;

async function writeBatchRequestsToFile(requests = [{ key: '', request: {} }], filePath = '') {
    try {
        // Use a writable stream for efficiency, especially with larger files.
        const writeStream = fs.createWriteStream(filePath, { flags: 'w' });

        writeStream.on('error', (err = null) => {
            console.error(`Error writing to file ${filePath}:`, err);
        });

        for (const req of requests) {
            writeStream.write(JSON.stringify(req) + '\n');
        }

        writeStream.end();

        console.log(`Successfully wrote batch requests to ${filePath}`);

    } catch (error) {
        // This catch block is for errors that might occur before stream setup,
        // stream errors are handled by the 'error' event.
        console.error(`An unexpected error occurred:`, error);
    }
}

// Write to a file.
await writeBatchRequestsToFile(requests, filePath);

// Upload the file to the File API.
const uploadedFile = await ai.files.upload({file: 'my-batch-requests.jsonl', config: {
    mimeType: 'jsonl',
}});
console.log(uploadedFile.name);

    監控工作狀態¶

    使用建立批次工作時取得的作業名稱來輪詢其狀態。 批次工作的 state 欄位會指出目前狀態。批次工作 可能處於下列任一狀態：

    • JOB_STATE_PENDING：工作已建立，正在等待服務處理。
    • JOB_STATE_RUNNING：工作正在進行中。
    • JOB_STATE_SUCCEEDED：工作已成功完成，現在可以擷取結果。
    • JOB_STATE_FAILED：工作失敗。請查看錯誤詳細資訊以瞭解更多。
    • JOB_STATE_CANCELLED：工作已由使用者取消。
    • JOB_STATE_EXPIRED：工作已過期，因為執行中或待處理的時間 超過 48 小時。這個工作不會有任何結果可供擷取。 你可以嘗試重新提交工作，或將請求拆分成 較小的批次。

    你可以定期輪詢工作狀態，確認工作是否完成。

    技術細節¶

    • 支援的模型：Batch API 支援多種 Gemini 模型。 每個模型對 Batch API 的支援情況，請參閱模型頁面。 Batch API 支援的模態與互動式（非批次）API 支援的模態相同。

    • 定價：Batch API 的費用為對應模型標準互動式 API 費用的 50%。詳情請參閱定價頁面。 這項功能的速率限制詳情，請參閱速率限制頁面。

    • 服務水準目標 (SLO)：批次工作的設計目標是在 24 小時內完成。許多工作可能會快得多， 視其大小與目前的系統負載而定。

    • 快取：批次請求支援上下文快取。 在批次中個別請求的設定裡指定 cached_content 資源名稱，即可重複使用已快取的內容。 如果批次中的某個請求命中快取，你只需支付 標準的上下文快取費率。

    最佳做法¶

    • 大量請求請使用輸入檔案：請求數量龐大時， 一律使用檔案輸入 方式，以便管理，也避免觸及 BatchGenerateContent 呼叫本身的請求大小上限。請注意，每個輸入檔案的大小上限為 2GB。

    • 錯誤處理：工作完成後，檢查 batchStats 中的 failedRequestCount。 如果使用檔案輸出，請逐行剖析，確認每一行是 GenerateContentResponse，還是表示該請求發生錯誤的狀態物件。 完整的錯誤代碼請參閱疑難排解 指南。

    • 工作只提交一次：建立批次工作不具冪等性。 如果你將相同的建立請求送出兩次，就會建立兩個獨立的批次工作。

    • 拆分超大型批次：雖然目標處理時間為 24 小時，實際處理時間會依系統負載與工作大小而有所不同。 對於大型工作，如果需要提早取得中間結果， 請考慮將其拆分成較小的批次。
