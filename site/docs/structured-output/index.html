    結構化輸出¶

    你可以設定 Gemini 模型，讓它產生的回應遵循你提供的 JSON Schema。這能確保結果可預測且具備型別安全，也讓從非結構化文字中 擷取結構化資料變得更簡單。

    結構化輸出特別適合用於：

    • 資料擷取：從文字中提取姓名、日期等特定資訊。
    • 結構化分類：將文字歸入預先定義的類別。
    • 代理工作流程：為工具或 API 產生結構化輸入。

    除了 REST API 支援 JSON Schema 之外，Google GenAI SDK 也 讓你使用下列函式庫定義結構描述： Pydantic (Python) and Zod (JavaScript).

    如果你需要是／否機率、單選選項，或附帶 校準後信賴度且不耗用輸出權杖的評分量表分數，請使用 Gemini Decision 1 模型搭配 Decisions API.

    食譜擷取器¶

    這個範例示範如何運用基本的 JSON Schema 型別，例如 object、array、 string 與 integer，從文字中擷取結構化資料。

    from google import genai
from pydantic import BaseModel, Field
from typing import List, Optional

class Ingredient(BaseModel):
    name: str = Field(description="Name of the ingredient.")
    quantity: str = Field(description="Quantity of the ingredient, including units.")

class Recipe(BaseModel):
    recipe_name: str = Field(description="The name of the recipe.")
    prep_time_minutes: Optional[int] = Field(description="Optional time in minutes to prepare the recipe.")
    ingredients: List[Ingredient]
    instructions: List[str]

client = genai.Client()

prompt = """
Please extract the recipe from the following text.
The user wants to make delicious chocolate chip cookies.
They need 2 and 1/4 cups of all-purpose flour, 1 teaspoon of baking soda,
1 teaspoon of salt, 1 cup of unsalted butter (softened), 3/4 cup of granulated sugar,
3/4 cup of packed brown sugar, 1 teaspoon of vanilla extract, and 2 large eggs.
For the best part, they'll need 2 cups of semisweet chocolate chips.
First, preheat the oven to 375°F (190°C). Then, in a small bowl, whisk together the flour,
baking soda, and salt. In a large bowl, cream together the butter, granulated sugar, and brown sugar
until light and fluffy. Beat in the vanilla and eggs, one at a time. Gradually beat in the dry
ingredients until just combined. Finally, stir in the chocolate chips. Drop by rounded tablespoons
onto ungreased baking sheets and bake for 9 to 11 minutes.
"""

interaction = client.interactions.create(
    model="gemini-4-hydrogen",
    input=prompt,
    response_format={
        "type": "text",
        "mime_type": "application/json",
        "schema": Recipe.model_json_schema()
    },
)

recipe = Recipe.model_validate_json(interaction.output_text)
print(recipe)

    JSON Schema 支援¶

    若要產生 JSON 物件，請將 response_format 設定為型別 text 的物件（或包含 物件的陣列），並將其 mime_type 設為 application/json。結構描述應放在 schema 欄位中提供。

    Gemini 的結構化輸出模式支援 JSON Schema 規格的 一部分子集。

    以下是支援的 type 值：

    • string：文字。
    • number：浮點數。
    • integer：整數。
    • boolean：true 或 false 值。
    • object：以鍵值對表示的結構化資料。
    • array：項目清單。
    • null：若要允許某個屬性為 null，請在型別陣列中加入 "null" (e.g., {"type": ["string", "null"]}).

    下列描述性屬性有助於引導模型：

    • title：屬性的簡短說明。
    • description：屬性較長且較詳細的說明。

    依類型而異的屬性¶

    object 型別的值：

    • properties：一個物件，其中每個鍵是屬性名稱，每個值 則是該屬性的結構描述。
    • required：字串陣列，列出哪些屬性為必填。
    • additionalProperties：控制是否允許未列在 properties 中的屬性。可以是布林值或結構描述。
    • 不支援的計數限制：minProperties 與 maxProperties 在 受限解碼期間不會強制執行，伺服器會忽略它們。 如有需要，請在應用程式程式碼中驗證屬性數量。

    string 型別的值：

    • enum：列出分類任務可用的特定字串集合。
    • format：指定字串的語法格式，例如 date-time、date、 time.
    • 不支援的長度限制：minLength 與 maxLength 在受限解碼 期間不會強制執行，伺服器會忽略它們。 如有需要，請在應用程式程式碼中驗證字串長度。

    number 與 integer 型別的值：

    • enum：列出可用的特定數值集合。
    • minimum：最小值（包含該值）。
    • maximum：最大值（包含該值）。

    array 型別的值：

    • items：定義陣列中所有項目的結構描述。
    • prefixItems：定義前 N 個項目的結構描述清單，可用來 建立類似 tuple 的結構。
    • minItems：陣列中的最少項目數。
    • maxItems：陣列中的最多項目數。
    • 不支援的陣列限制：uniqueItems、contains、minContains 與 maxContains 在受限解碼期間不會強制執行，伺服器會 忽略它們。如有需要，請在應用程式程式碼中去除重複項目 或檢查陣列內容。

    結構化輸出與函式呼叫的比較¶

    功能 主要使用情境
    結構化輸出 格式化最終回應：當你希望模型的回答採用特定格式時使用。
    函式呼叫 在對話過程中採取行動：當模型需要先請你執行某項任務、再給出最終回答時使用。

    最佳做法¶

    • 清楚的說明：使用 description 欄位引導模型。
    • 明確的型別：使用具體的型別（integer、string、enum）。
    • 提示詞設計：清楚說明你希望模型做什麼。
    • 驗證：輸出雖是語法正確的 JSON，仍應一律在應用程式中 驗證其值。
    • 錯誤處理：針對符合結構描述但語意不正確的輸出， 實作完善的錯誤處理。

    限制¶

    • 結構描述子集：並非所有 JSON Schema 功能都受支援。
    • 結構描述複雜度：過大或巢狀過深的結構描述可能會被拒絕。
    • 不強制執行的限制：minLength、maxLength、minProperties、 maxProperties、uniqueItems、contains、minContains 與 maxContains （以及它們的 snake_case 變體）不會由受限解碼文法引擎 強制執行。如果你的結構描述中含有這些關鍵字（例如 Pydantic 的 Field(min_length=...) 或 Zod 的 .min() 自動產生的），API 會在要求正規化期間自動將其移除並 忽略，而不會回傳錯誤。minItems 與 maxItems 則會 強制執行。若要強制執行其他限制，請在用戶端應用程式中驗證 輸出（例如使用 Pydantic 的 model_validate_json() 或 Zod 的 .parse()）。

    簡化複雜的結構描述¶

    當你要求結構化輸出時，API 會將你的 JSON Schema 編譯成 一個限制權杖產生的狀態機。這個狀態機會對總狀態數、 分支路徑與巢狀深度設下上限。如果你的結構描述 超出這些上限，API 會以 400 INVALID_ARGUMENT 錯誤拒絕要求。

    若要修正結構描述被拒絕的錯誤，請降低結構描述的結構深度與 分支程度。你可以用以下幾種方式簡化複雜的結構描述：

    • 將非結構性規則移入說明：欄位的 description 屬性 與系統指令能引導模型，又不會為輸出文法增加狀態。 如果複雜的限制讓你的結構描述超出上限，請將這些 規則寫成簡潔的說明，並在應用程式程式碼中驗證 回應。
    • 攤平巢狀物件並限制遞迴：將深層巢狀的物件階層 改為較扁平的結構。如果你在遞迴型別中使用 $defs 與 $ref， 請將遞迴參照設為選用或可為 null。避免 透過必填屬性，或 minItems 大於 零的陣列進行遞迴。
    • 減少選用欄位、列舉與聯集造成的分支：選用 屬性、enum 值與 anyOf 分支會讓輸出文法的分支路徑倍增。 請盡可能將屬性標示為 required，並在欄位可為空時 允許 null 值。精簡過大的 enum 清單、簡化 anyOf 聯集，或將限制寫入提示詞中（例如搭配 Pydantic 結構描述），作為較寬鬆的限制。
    • 縮短屬性名稱並移除陣列或數值界限：屬性鍵 消耗的狀態數與其字元長度成正比。minItems 與 maxItems 等 陣列界限會為每個計數位置複製一份項目結構描述， 數值界限（minimum 與 maximum）也會擴大 狀態空間。請使用簡潔的屬性名稱、移除未使用的欄位，並將 界限寫入提示詞中（例如搭配 Pydantic 結構描述）作為 較寬鬆的限制，或在應用程式程式碼中驗證界限。
