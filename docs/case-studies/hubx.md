# HubX 整合 Gemini 2.5 Flash Image，實現低延遲、具情境理解的照片編輯

[HubX](https://hubx.co/) 是一家全球科技中心，透過其行動應用程式產品組合服務超過 3 億名使用者。在開發最新應用程式 ReShoot 時，他們的目標是運用生成式 AI，讓專業級的照片編輯普及化。透過 Gemini API，該團隊展現了驚人的開發速度，從 MVP 開發開始到在 iOS 正式上線，僅僅花了兩週時間。不久之後，ReShoot 在 App Store 美國區的「圖形與設計」類別中奪得第一名。這款應用程式的目標是讓使用者能改變照片的場景或風格，同時不失去原始主體的自然外觀與身分特徵。對開發人員而言，要在行動體驗嚴格的低延遲要求下，實現這種層級的複雜多模態推理，是一項重大的架構挑戰。為了解決這個問題，HubX 運用 Gemini API 打造了一條精密的照片編輯管線，兼顧高保真度的情境理解與卓越的推論速度。

![HubX](https://www.gstatic.com/aistudio/case_studies/hubx/hubx_01.jpg)

## 以 Nano Banana 實現高保真度編輯

為了打造 ReShoot 背後的推理引擎，HubX 與 Google 團隊合作，整合了 **Gemini 2.5 Flash Image**，也就是 **Nano Banana**。圖像轉圖像生成的一大技術挑戰，是在解讀複雜場景要求的同時維持主體的身分特徵。不同於傳統管線往往需要串連不同模型分別處理文字推理與圖像合成，Gemini 2.5 Flash Image 是原生多模態的。它在單一、統一的步驟中處理文字提示詞與圖像輸入。這種架構讓 ReShoot 能進行對話式編輯（圖像＋文字轉圖像），高度遵循使用者的提示詞，同時保留上傳照片的核心身分特徵與情境。相較於測試過的其他方案，HubX 發現 Gemini 模型提供了更優異的視覺理解能力與多模態一致性。

## 將應用程式延遲降低 40%

高保真度生成固然是必要條件，但行動使用者期待的是近乎即時的結果。創作流程中的任何阻力都可能導致參與度流失。透過全面採用 Gemini 2.5 Flash Image，HubX 將更新與處理圖像的平均回應時間縮短了近 40%。這項關鍵的延遲改善，將使用者體驗從被動等待的狀態轉變為流暢的創作流程，這對消費級行動應用程式的使用者留存至關重要。

## 簡化開發工作流程

除了即時的效能提升之外，整合 Gemini API 也大幅簡化了 HubX 的開發架構。團隊運用 [Google AI Studio](https://aistudio.google.com/app) 製作提示詞鏈的原型並進行測試，再透過連接到其行動後端的自訂 Node.js 套件部署到正式環境。在使用 Gemini 模型之前，涉及多模態資料解讀的任務往往需要複雜的自訂邏輯，或串連多個不同的模型。採用 **Gemini 2.5 Flash Image** 後，HubX 將這些任務整合到單一、連貫的建模框架中，降低了架構複雜度，同時提升了推論速度。

## 後續展望

成功整合 Gemini API 後，HubX 觀察到使用者參與度提升，生成內容的儲存與按讚率都提高了。展望未來，他們計畫將 ReShoot 從單一用途的工具，發展為原生、無縫照片編輯的綜合平台。HubX 的實作展現了開發人員如何運用 Gemini API 的速度與原生多模態能力，打造直覺、高效能的應用程式，滿足行動使用者的需求。若要開始使用 Gemini 模型建構，請參閱我們的[圖像生成文件](/docs/image-generation/)。
